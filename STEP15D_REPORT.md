## Search integration
The existing SearchEngine is the single, authoritative search/filter logic. The
UI only forwards criteria (`text`, `classes`, `minConfidence`, `sortBy/sortDir`)
to `search()` and renders `SearchResult[].record`. No second search logic, no
UI-side filter reimplementation, no direct IndexStore use as a search
replacement, no custom parser.

## Classification filter
Reuses the exact existing taxonomy (Drums/Musical/Other groups + individual
classes from `classFilterOptions()`, derived from `TAXONOMY`). Selected values
are passed through to the SearchEngine's `classes` (goal: optional, runs via
the SearchEngine).

## Confidence filter
Uses `SearchQuery.minConfidence` (1–100% numeric input, `0..1`). No new
confidence computation — purely forwarded.

## Status filter
Not implemented. The SearchEngine default (analyzed) is left untouched, exactly
as the spec allows ("not required for DONE"); no new queue logic.

## Selection
- A selected sample hidden by a filter is cleared (no hidden selection state
  for invisible samples). Applied to both single selection and multi-select
  (multi-select is pruned to the visible set; single selection clears when the
  sample disappears).
- A selected sample that stays visible keeps its selection.

## Empty states
Two distinct messages, distinguished by whether any search/filter is active:
- No analyzed samples: "No analyzed samples yet."
- No matches: "No samples match your search."
Both generated by pure `emptyStateMessage(hasActiveSearch(state))`.

## Result count
Displayed as `${n} sample(s)` derived from the current `SearchEngine` results
(`resultCountLabel(app.results.length)`); no separate counting/index logic.
